# Sprint 1 实现说明

## 1. 项目概述
本项目是一个基于 Vue 3 (Composition API) 构建的“方舟服务台”工单管理系统。在 Sprint 1 阶段，我使用单文件组件（`App.vue`）实现了完整的工单核心业务流程，包含：工单列表浏览、多条件筛选、新建工单表单校验、工单详情展示以及操作时间轴。

项目采用纯前端实现，内置了基于 `localStorage` 的 Mock 数据持久化方案，同时预留了真实的 RESTful API 对接能力。

## 2. 完成功能模块
- 工单列表 (List)：
    - 支持按“工单编号”或“标题”进行关键字搜索。
    - 支持按“工单状态”进行下拉筛选。
    - 实现了加载状态（Loading）、错误重试（Error）以及空数据状态（Empty State）的友好提示。
    - 表格通过 CSS Grid 布局，实现了状态的徽标（Badge）渲染。
- 创建工单 (Create)：
    - 实现了表单双向绑定（`v-model`），包含标题、分类、优先级和问题描述。
    - 表单校验：标题至少 4 个字符，描述至少 10 个字符，带有实时字数统计和错误提示。
    - 实时预览：右侧边栏（Aside）能根据左侧表单输入实时展示“登记摘要”。
- 工单详情 (Detail)：
    - 展示工单的基础信息、状态和优先级标签。
    - 实现了基于操作日志的时间轴（Timeline）视图，直观展示工单流转过程。
- 全局体验优化：
    - 实现了路由切换（列表、创建、详情）。
    - 操作成功或失败时，右下角弹出 Toast 轻提示。
    - 页面全量响应式适配，支持 PC、平板（<900px）和手机（<600px）端无缝切换。

## 3. 技术栈说明
- 核心框架：Vue 3（`<script setup>` 语法糖，使用 `ref` 和 `reactive` 进行状态管理）。
- 样式方案：原生 CSS，使用 CSS Grid 和 Flexbox 进行页面布局，配合 `@media` 媒体查询实现响应式。
- 数据交互：原生 `fetch` 封装了 HTTP 请求，并设计了 `AbortController` 进行超时控制（12 秒）。
- 持久化：利用浏览器 `localStorage` 实现了 Mock 数据的本地存储与读取。

## 4. 核心代码实现逻辑

### 4.1 轻量级 Hash 路由管理
由于项目采用单文件组件，未引入第三方路由库，我基于 `window.location.hash` 手写了一个路由同步机制：
- 通过 `syncRoute()` 解析 URL 的 hash（如 `#/tickets`、`#/create`、`#/tickets/:id`）。
- 监听 `hashchange` 事件，动态改变 `page` 状态（`list`、`create`、`detail`），从而控制视图切换。

### 4.2 Mock API 与真实 API 切换设计
代码中通过环境变量 `VITE_USE_MOCK` 实现了数据层的解耦：
- 定义了统一的 `ticketApi` 对象。
- 当开启 Mock 模式时，调用 `mockApi`，利用 `setTimeout` 模拟网络延迟（240ms - 360ms），并读写 `localStorage`。
- 关闭 Mock 时，通过 `httpRequest` 发起真实请求，支持环境变量配置 API 基础路径。

### 4.3 表单校验与错误处理
`validateForm()` 函数集中处理了表单校验逻辑。除了基本的长度校验外，还考虑了分类和优先级的合法性，并通过 `nextTick` 在发生错误时自动将焦点（Focus）定位到第一个未通过校验的输入框，提升用户体验。

## 5. 遇到的难点与解决方案
- 难点 1：并发请求导致的数据渲染冲突
    - 解决：在加载列表和详情时，引入了自增的请求 ID（`listRequestId` / `detailRequestId`）。只有当前返回的请求 ID 与最新 ID 匹配时，才更新视图数据，避免了快速切换导致的数据错乱。
- 难点 2：移动端表格的展示
    - 解决：在屏幕宽度小于 600px 时，隐藏了原表格的表头，使用 CSS Grid 将每行数据重构为卡片式布局，并隐藏了部分次要字段（如处理人、更新时间），确保在手机端阅读舒适。

## 6. 运行说明
1. 确保已安装 Node.js 环境。
2. 安装依赖：`npm install`
3. 启动本地开发服务：`npm run dev`
*(项目默认开启 Mock 模式，无需后端支持即可完整体验)*
